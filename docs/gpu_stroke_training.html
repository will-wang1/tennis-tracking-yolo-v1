Stroke Model Training

Train the new stroke classifier on the GPU laptop: download 9 broadcast matches, turn E2E-Spot's ~9,800 labelled strokes into training data, train, and bring the model back to the Mac.

Commands are for Windows PowerShell. Run them in order. Code: branch claude/bounce-contact-classifier, commit 3e2a1a9 or later.

Your 73 Dingles labels are already turned into a test file (data/strokes/ours/dingles_serve_volley.npz). Training scores the model on them. It never trains on them, so the score is honest.

1Get the project onto the GPU laptop

The project folder is in OneDrive, so on a laptop signed in to the same OneDrive it is already there. Open PowerShell and go to it. The path is usually this; change it if your OneDrive folder is named differently:

PowerShell
cd "$env:USERPROFILE\OneDrive - Knox Grammar School\Documents\tennis-tracking-yolo-v1"
git log --oneline -1

The last line should show commit 3e2a1a9 or newer. If OneDrive is not on that laptop, copy the whole tennis-tracking-yolo-v1 folder across instead. It needs the weights folder.

Keep the Python environment and the downloaded videos outside OneDrive (the commands below use C:\venvs and C:\tennis_videos). Otherwise OneDrive will try to sync tens of gigabytes.

2Python with the GPU

Check the GPU and its CUDA version (top right of the output):

PowerShell
nvidia-smi

Make an environment and install PyTorch for CUDA. cu124 suits CUDA 12.4 and newer. If nvidia-smi shows an older version, pick the matching command at pytorch.org/get-started.

PowerShell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
py -3.12 -m venv C:\venvs\tennis-gpu
C:\venvs\tennis-gpu\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
pip install ultralytics opencv-python numpy scipy sympy

Check PyTorch sees the GPU. It should print True and the GPU's name:

PowerShell
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

In a new PowerShell window later, activate the environment again with C:\venvs\tennis-gpu\Scripts\Activate.ps1 and cd into the project (step 1).

3Download the 9 matches

Only the 9 matches that have stroke labels. The download is video only (no sound), 1080p, at up to 30 frames a second, to match what the labels were made on.

PowerShell, from the project folder
$videos = "C:\tennis_videos"
New-Item -ItemType Directory -Force $videos | Out-Null
Import-Csv data\external\e2e_spot_tennis\videos.csv | ForEach-Object {
  yt-dlp -f "bv*[height=1080][fps<=30][vcodec^=avc1]/bv*[height=1080][fps<=30]" `
         -o "$videos\$($_.name).%(ext)s" "https://www.youtube.com/watch?v=$($_.yt_id)"
}
Get-ChildItem $videos | Select-Object Name, @{n="GB";e={[math]::Round($_.Length/1GB,1)}}

You should end up with 9 files named after the matches, e.g. wimbledon_2019_mens_final_djokovic_federer.mp4. If one is no longer on YouTube, carry on; the next step skips it and says so. If yt-dlp says the format is not available, run yt-dlp -F <link> to list formats and send me the output.

4Quick check: do the videos line up with the labels?

The labels point at exact frames in the YouTube videos. If an upload was re-cut, the labels will point at the wrong moments. Check one match on 20 points first:

PowerShell
python scripts\build_stroke_data_e2e.py --videos C:\tennis_videos --out data\strokes\e2e_check `
  --matches wimbledon_2019_womens_final_halep_williams --max-points 20

Then open the picture it writes:

PowerShell
start data\strokes\e2e_check\wimbledon_2019_womens_final_halep_williams_preview.jpg
  • Good: each picture shows a player at the moment of the stroke named above it (a serve looks like a serve, a backhand like a backhand).
  • Bad: players standing around, crowd shots or replays. The video and labels do not line up; stop and tell me.
  • The last line printed also shows how many strokes were skipped and why. "no court" is a camera angle the court detector could not read; a few are normal.

5Build the training data

All 9 matches. This takes a few hours. It writes one file per match, and a finished match is skipped, so you can stop it (Ctrl+C) and run the same command again later to carry on.

PowerShell
python scripts\build_stroke_data_e2e.py --videos C:\tennis_videos --out data\strokes\e2e

Each match writes a _preview.jpg next to its data. Glance at a couple as they finish, as in step 4. When all 9 are done you can delete C:\tennis_videos, since training does not need the videos.

If it runs out of GPU memory, open scripts\build_stroke_data_e2e.py, change BATCH = 16 to BATCH = 4, and run the same command again.

6Train

Trains on 8 matches, holds the 9th out to check itself each round, and finally scores it on your Dingles labels:

PowerShell
python scripts\train_stroke_tcn.py --train "data/strokes/e2e/*.npz" `
  --val-match wimbledon_2019_womens_final_halep_williams `
  --test data/strokes/ours/dingles_serve_volley.npz --out weights/stroke_tcn.pt

Each round prints an accuracy on the held-out match. It should climb over the first 10–20 rounds. At the end it prints a score per stroke on Dingles, and saves weights\stroke_tcn.pt and weights\stroke_tcn.json (all the scores).

7Bring the model back

weights\stroke_tcn.pt and weights\stroke_tcn.json are in the project folder, so OneDrive syncs them to the Mac by itself. Tell Claude once they are there. It will compare the new model with BST on your labels and wire it into the pipeline if it wins.

If the folder was copied rather than synced, copy those two files into the Mac's tennis-tracking-yolo-v1\weights folder.

[missing] <match>That video did not download; fine to carry on without it.
Mostly "no court" or "player not found" skipsSend me the printed lines and the preview picture.
